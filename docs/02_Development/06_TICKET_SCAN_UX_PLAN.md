# 티켓 검표 화면 UX 개선 계획

## 배경

현재 검표 화면(`/[locale]/(scanner)/my-tickets/[ticketId]/scan/page.tsx`)은 기능은 동작하지만 실제 검표 현장 시나리오에 맞지 않는 UX 문제가 있다.

---

## 완료된 UI 정리 (Phase 0)

- 결과 패널 배지를 영문 enum 그대로(`SUCCESS`, `ALREADY_USED` 등) 출력하던 것을 번역 키로 교체
  - 추가된 키: `scanResultSuccess`, `scanResultAlreadyUsed`, `scanResultInvalid`, `scanResultExpired`, `scanResultWrongTicket`, `scanResultNotOpen`, `scanResultForbidden`
  - 적용 파일: `messages/ko.json`, `messages/en.json`, `messages/ja.json`

---

## 현재 UX 문제 목록

| # | 문제 | 영향 |
|---|------|------|
| 1 | 결과 패널이 화면 하단으로 밀려 스크롤이 필요함 | 검표원이 성공/실패를 즉시 확인하기 어려움 |
| 2 | 카메라 상태 배너가 비디오 밖 별도 줄 차지 | 세로 공간 낭비, 카메라 영역 축소 |
| 3 | 제출 중 피드백이 약하고 결과 위계가 복잡함 | 현장에서 상태 전환을 빠르게 읽기 어려움 |
| 4 | 성공 후 입력값 자동 초기화 없음 | 연속 스캔 시 이전 토큰이 잔존 |
| 5 | 결과 피드백이 카메라를 가리면 다음 스캔 동선이 끊김 | 연속 검표 속도 저하 |
| 6 | 성공/실패를 화면 변화나 소리로 즉시 구분하기 어려움 | 시끄럽거나 어두운 현장에서 인지성 저하 |

## 개선 계획

### Phase 1 — 한 화면 고정형 단순 레이아웃

**목표:** 스크롤 없이 한 화면에서 카메라와 검표 결과를 동시에 본다.

**핵심 원칙:**

- 페이지 전체를 `100dvh` 기준으로 고정하고 세로 스크롤을 없앤다.
- 검표에 직접 필요 없는 설명, 여백, 중복 텍스트를 줄인다.
- 결과는 아래로 밀어내는 방식이 아니라 화면 안의 고정 영역에 표시한다.

**구현 방법:**

1. **뷰포트 고정 레이아웃**
   - 루트 컨테이너를 `min-h-[100dvh]` 또는 `h-[100dvh]` 기준으로 재구성
   - `overflow-y-auto` 대신 `overflow-hidden` 기반으로 구성
   - 상단은 카메라, 하단은 축약된 결과 패널의 2단 구조로 고정

2. **카메라 영역 중심 배치**
   - 카메라 프리뷰를 화면의 주 영역으로 유지하고 결과 패널은 하단 compact 영역으로 제한
   - `scannerStatus`, 제출 중 상태, 권한 메시지는 비디오 내부 오버레이 칩으로 통합
   - 비디오 바깥 별도 상태 줄은 제거

3. **결과 패널 단순화**
   - 결과 패널은 `상태`, `짧은 설명`, `최근 검표 시각/티켓 번호` 정도만 노출
   - 장식성 요소보다 가독성을 우선하고 패딩과 텍스트 위계를 단순하게 조정
   - 성공/실패 색상 대비는 유지하되 카드 높이는 제한

4. **수동 입력 UI 축소**
   - QR 자동 스캔이 기본 흐름이 되도록 수동 입력은 접기 가능하거나 보조 영역으로 축소
   - 자주 쓰지 않는 버튼이나 안내 문구는 1차 화면에서 제외

**검증:**
- 세로가 짧은 모바일 화면에서도 스크롤이 발생하지 않는지 확인
- 카메라와 최근 결과가 동시에 항상 보이는지 확인
- 제출 중/오류 상태가 별도 줄 없이도 인지 가능한지 확인

---

### Phase 2 — 카메라 비가림 없는 연속 스캔 UX

**목표:** 연속 검표 중에도 카메라 화면이 항상 살아 있고 UI가 시야를 막지 않도록 한다.

**핵심 원칙:**

- 전체화면 모달처럼 카메라를 완전히 덮는 UI는 사용하지 않는다.
- 결과 피드백은 짧고 강하게 주되 카메라 프리뷰는 계속 보여준다.
- 다음 사람의 QR을 바로 가져갈 수 있도록 성공 직후 복귀 시간을 최소화한다.

**구현 방법:**

1. **전체화면 모달 제거**
   - 기존 계획의 fullscreen 결과 오버레이는 폐기
   - 결과는 카메라 위 가장자리 배너 또는 하단 compact 패널에서만 노출

2. **비가림 최소 오버레이**
   - 성공/실패 피드백은 상단 또는 하단의 얇은 토스트 형태로 1~1.5초 표시
   - 오버레이 높이는 화면의 작은 일부만 차지하도록 제한
   - 반투명 배경을 써도 QR 인식 영역 중앙은 가리지 않음

3. **연속 스캔 복귀 흐름**
   - 성공 후 `qrToken`을 자동 초기화하고 짧은 지연 뒤 즉시 재스캔 대기 상태로 복귀
   - 수동 입력을 사용한 경우에도 입력 포커스를 자동 복귀
   - 중복 스캔 방지를 위해 아주 짧은 debounce 또는 cooldown만 둠

4. **스캔 상태 시각화**
   - QR 인식 순간 카메라 프레임 테두리 또는 스캔 가이드에 짧은 flash 효과 적용
   - 요청 중에는 작은 spinner/chip만 유지하고 중앙 영역을 막는 로더는 사용하지 않음

**검증:**
- 5회 이상 연속 검표 시 화면 탭 없이 흐름이 이어지는지 확인
- 결과 표시 중에도 카메라 중앙 인식 영역이 계속 보이는지 확인
- 성공/실패 후 다음 스캔 대기 상태로 빠르게 복귀하는지 확인

---

### Phase 3 — 시각 변화 + 비프음 피드백

**목표:** 햅틱보다 현장성이 높은 시각 변화와 비프음으로 성공/실패를 즉시 구분한다.

**구현 방법:**

1. **강한 시각 변화**
   - 성공 시 초록 계열 flash, 실패 시 빨강 계열 flash를 카메라 프레임과 결과 패널에 짧게 적용
   - 상태 배지 변경만으로 끝내지 않고 화면 전체 톤이 순간적으로 바뀌는 피드백 제공

2. **비프음 재생**
   - 성공: 짧은 단일 비프음
   - 실패: 더 낮거나 두 번 울리는 비프음
   - 구현은 경량 오디오 자산 또는 Web Audio API 중 단순한 방식 우선

3. **현장 제어 옵션**
   - 공연장 환경에 맞게 음소거 토글 또는 볼륨 제어 진입점을 제공
   - 기본값은 운영 정책에 따라 결정하되, 음향 피드백 자체는 기본 지원 범위에 포함

4. **햅틱은 후순위**
   - `navigator.vibrate` 기반 햅틱은 이번 핵심 범위에서 제외
   - 필요 시 추후 선택 기능으로 별도 검토

**검증:**
- 성공/실패를 소리 없이도 화면 변화만으로 구분 가능한지 확인
- 화면을 보지 못한 순간에도 비프음만으로 결과 인지가 가능한지 확인
- 모바일 브라우저에서 오디오 재생 제약 없이 동작하는지 확인

## 우선순위 및 일정

| Phase | 내용 | 우선순위 | 예상 공수 |
|-------|------|----------|-----------|
| 0 | 번역 키 추가 (완료) | — | 완료 |
| 1 | 한 화면 고정형 레이아웃 + 결과 패널 단순화 | 매우 높음 | 2-3h |
| 2 | 카메라 비가림 없는 연속 스캔 UX | 매우 높음 | 2-3h |
| 3 | 시각 변화 + 비프음 피드백 | 높음 | 1-2h |
