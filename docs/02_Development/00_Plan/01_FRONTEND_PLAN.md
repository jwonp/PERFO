# PERFO 프론트엔드 개발 계획

> 기준 문서:
> `docs/01_Design/00_Architecture/03_FSD.md`
> `docs/01_Design/00_Architecture/04_REQUEST_PROCESSING_STRATEGY.md`
> `docs/01_Design/00_Architecture/02_AUTH_ACCOUNT_STRATEGY.md`

## 1. 목표

- Next.js 기반 사용자 화면과 관리자 화면을 구현한다.
- 백엔드 계약과 동일한 상태 모델을 사용한다.
- 실시간 티켓팅 상태는 `SSE` 중심으로 처리한다.
- 프론트 구조는 목표 FSD 구조를 기준으로 점진 정리한다.

## 2. 선행 작업

- 라우팅 구조 확정
- 인증 흐름 확정
- 소셜 최초 가입 후 약관/프로필 입력 화면 확정
- 계정 연동/해제 UX 확정
- 공통 API 응답 형식 확정
- 티켓팅 상태 enum 확정
- A/B variant 주입 방식 확정

## 3. 구현 범위

### 3.1 공통 기반

- `app/`, `widgets/`, `features/`, `entities/`, `shared/`, `server/` 구조 정리
- 공통 레이아웃, 내비게이션, 인증 가드 정리
- API 클라이언트, 에러 처리, 로딩 상태 처리 정리

### 3.2 사용자 기능

- 로그인/로그아웃
- 일반 회원가입
- 소셜 최초 가입 후 약관 동의와 `displayName` 입력
- 계정 연동/해제
- 이벤트 목록 조회
- 티켓 예약/발급 요청
- 내 티켓 목록 조회
- 티켓 상태 표시
- QR 표시

### 3.3 관리자 기능

- 운영 관리자 조회 화면
- 재처리 요청 화면
- 시스템 관리자 전용 운영 화면 분리

### 3.4 실시간 처리

- SSE 연결 훅 또는 모듈 구현
- 상태별 UI 전이 정의
- Polling fallback 처리
- 네트워크 복구 시 SSE 재연결 처리

### 3.5 A/B 테스트

- `userId` 기준 variant 반영
- variant별 UI 컴포넌트 분기
- 실험 지표 전송 포인트 정의

## 4. 작업 순서

1. FSD 골격과 공통 레이아웃 정리
2. 인증 흐름 연결
3. 이벤트/티켓 목록 화면 구현
4. 티켓팅 요청 UI와 상태 표시 구현
5. SSE와 Polling fallback 연결
6. 관리자 화면 구현
7. A/B 테스트 분기와 이벤트 수집 연결

## 5. 세부 작업 체크리스트

### 5.1 구조 정리

- `shared`와 `server` 경계 반영
- `server-only` 모듈 분리
- 새 코드 Public API 규칙 적용

### 5.2 상태 관리

- 인증 상태 관리
- 소셜 최초 가입 임시 상태 관리
- 계정 연동/해제 진행 상태 관리
- 티켓 상태 관리
- SSE 연결 상태 관리
- fallback 상태 관리

### 5.3 UX

- 티켓팅 진행 상태 시각화
- 실패와 재시도 가능 여부 표시
- Polling fallback 중 일관된 상태 표시
- 검증 결과 화면 정리

## 6. 완료 기준

- 프론트가 백엔드 상태 계약과 일치한다.
- 티켓팅 상태가 SSE와 Polling fallback에서 모두 동일하게 보인다.
- 관리자와 일반 사용자 권한 분기가 화면에서 명확하다.
- 새 프론트 코드가 목표 FSD 구조를 따른다.

## 7. 보류 가능 항목

- 복잡한 시각 효과
- 관리자 대시보드 고도화
- 고급 분석 대시보드
- 실험 통계 시각화
